# IPv6 Multi-Router Lab: Anycast, SLAAC, EUI-64, OSPFv3

A Cisco Packet Tracer lab built while studying IPv6 (Jeremy's IT Lab CCNA course, Day 32). The goal was to combine everything learned so far in IPv6 into one network: addressing, link-local addresses, EUI-64, SLAAC, OSPFv3 routing, and an anycast address shared by two routers.

## What this lab covers

- Manual global unicast addressing on routers and servers
- Automatically generated link-local addresses (`FE80::/10`) on every IPv6-enabled interface
- EUI-64 interface ID generation on a router interface
- SLAAC on PCs (Auto Config) using Router Advertisements
- Dynamic routing with OSPFv3 instead of static IPv6 routes
- Anycast: the same `/128` address on the loopback of two routers, advertised through OSPFv3
- Verification with `ping`, `tracert`, `ipconfig`, and `show ipv6 ...` commands



Devices: 4 routers (2911), 4 switches (2960), PCs, and servers.

| Link 14 | `2001:DB8:14::/64` | R1 `::1`, R4 `::4` |
| LAN A | `2001:DB8:A::/64` | R2 `::1` (manual), Srv-W `::10`, PCs via SLAAC |
| LAN B | `2001:DB8:B::/64` | R3 via EUI-64, Srv-E `::10`, PCs via SLAAC |
| LAN D | `2001:DB8:D::/64` | R4 `::1`, Srv-D1 `::10`, Srv-D2 `::20`, PC-D1 `::11` |
| Anycast | `2001:DB8:100::53/128` | Loopback0 on R2 and R3 |

## Routing

Routing between all sites is done with OSPFv3 (area 0) on R1, R2, R3, and R4, with no static IPv6 routes. The LANs and the anycast loopbacks of R2 and R3 are learned by OSPFv3, so the network decides the path by itself.
